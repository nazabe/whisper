# Step 1 — Convert `main.py` into a FastAPI Whisper Microservice

## 1. Context

`main.py` is currently a batch script that couples four concerns:

1. Audio transcription with `faster-whisper`.
2. Writing a Markdown transcript to a hardcoded path.
3. Reading that file back and calling an LLM (DeepSeek).
4. Parsing and writing an analysis JSON.

It also hardcodes input/output filenames and an API key.

Step 1 extracts **only transcription** into a stateless HTTP service. Analysis, MongoDB, job queues, audio storage, authentication, and diarization remain out of scope and are handled in later steps.

### Goal

Expose a reliable, typed, CPU-friendly transcription service that the Bun/Fastify backend can call per job, returning the exact JSON shape that will later be persisted in MongoDB.

### Non-goals

- No DeepSeek/LLM call.
- No MongoDB client.
- No queue, retries, or job state.
- No audio persistence (caller owns the file).
- No auth, rate limiting, or multi-tenant logic.
- No speaker diarization.

---

## 2. Framework decision: FastAPI vs Flask

### Decision

Use **FastAPI + Pydantic v2 + Uvicorn** with a single worker and a bounded concurrency semaphore.

### Rationale

Neither framework is installed today; Pydantic 2.13.5 is. FastAPI adds Starlette, Uvicorn, and `python-multipart`; Flask adds Werkzeug, Jinja2, and Click. Dependency weight is comparable.

The choice is **not** driven by throughput. Inference takes minutes; framework overhead is milliseconds and therefore irrelevant. The decision is driven by the service's actual deliverable: a stable, typed JSON contract consumed by Bun/Fastify and later persisted in MongoDB.

| Criterion | Weight | FastAPI | Flask |
|---|---|---|---|
| Typed JSON contract + OpenAPI | High | Native Pydantic, `response_model`, generated `/docs` | Requires flask-smorest/marshmallow or manual validation |
| Long multipart uploads | Medium | `UploadFile` spooled to disk, `async` endpoint | `request.stream` works but is more manual |
| Blocking inference | High | `asyncio.to_thread` + semaphore | Explicit `ThreadPoolExecutor` or Gunicorn threads |
| Risk of blocking the process | Medium | High if `to_thread` is forgotten | Low: synchronous by design |
| Mental model / debuggability | Medium | Two models (async + thread) | One synchronous model |
| ML/Whisper ecosystem | Low | Majority of examples and deployments | Fewer examples, still viable |
| Trivial-endpoint throughput | Low | Higher | Lower, irrelevant here |
| Affinity with Bun + Fastify | Medium | ASGI async, DI, schemas: similar model | WSGI sync: paradigm change |

Decisive arguments for FastAPI:

1. The same Pydantic model validates requests, serializes responses, and generates OpenAPI. The contract cannot silently drift from the code.
2. It avoids introducing Marshmallow or hand-rolled validation for what Pydantic already does.
3. The Bun/Fastify backend already uses declarative schema validation (Zod). Pydantic preserves the same mental model and reduces context switching.
4. If live progress (SSE/WebSocket) is added later, ASGI supports it without changing frameworks.

### When Flask would be the better choice

- The team knows Flask deeply and wants minimal framework magic.
- A fully synchronous model is preferred to make blocking explicit.
- The async equivalent of Flask (Quart) is not desired and its smaller ecosystem is acceptable.
- Minimal dependency surface is a hard requirement.

Flask 3 is a valid choice and would not be a technical mistake. The architecture below (stateless service, one model, concurrency 1, typed contract) is framework-independent. Choosing Flask would only change the framework and the way inference is offloaded to an executor.

### Operational cost of FastAPI

- Every `faster-whisper` call must go through `asyncio.to_thread`; otherwise the event loop blocks and health checks stop responding.
- `uvicorn --workers 1` is mandatory: each worker loads another model copy and multiplies RAM usage.
- Concurrency is controlled by the semaphore, not by adding workers.
- Error handling must translate decode failures to `400` and must not leak tracebacks.

## 6. API contract

### `GET /health`

Returns service and model readiness:

```json
{
  "status": "ok",
  "model": "small",
  "device": "cpu",
  "compute_type": "int8",
  "model_loaded": true
}
```

- `200` when the model is loaded.
- `503` with `model_loaded: false` while loading or after a failed load.

### `POST /transcribe`

`multipart/form-data`:

| Field | Type | Required | Notes |
|---|---|---|---|
| `file` | file | yes | Audio payload; streamed to a temp file. |
| `language` | string | no | Overrides `WHISPER_LANGUAGE`; `auto` disables the default. |

Success `200`:

```json
{
  "language": "es",
  "language_probability": 1.0,
  "duration_sec": 661.76,
  "model": "small",
  "compute_type": "int8",
  "text": "full concatenated transcript",
  "segments": [
    { "id": 0, "start": 0.0, "end": 5.04, "text": "..." }
  ]
}
```

- `segments` are ordered and materialized, never a generator.
- `start`/`end` are seconds as floats, matching `main.py`.
- `text` is segments joined with a single space (convenience for the caller).
- No file paths, filenames, or raw model objects are returned.

Errors (consistent body `{"detail": "..."}`):

| Status | Cause |
|---|---|
| `400` | Empty file, unsupported content type, unreadable audio. |
| `413` | Exceeds `WHISPER_MAX_UPLOAD_MB`. |
| `422` | FastAPI validation error. |
| `503` | Queue wait exceeded or model not ready. |
| `500` | Unexpected inference failure. |

### `GET /` (optional)

Returns service name and version only. Keep `/docs` enabled by default for internal use; revisit exposure before any public deployment.

## 7. Implementation plan

### 7.1 `schemas.py`

- `Segment`: `id: int`, `start: float`, `end: float`, `text: str`.
- `TranscribeResponse`: fields above.
- `HealthResponse`: fields above.
- Use `Field` descriptions; no custom serializers needed.
- Do not expose `info` objects or provider-specific structures.

### 7.2 `transcriber.py`

```python
class WhisperTranscriber:
    def __init__(self, settings: Settings): ...
    def load(self) -> None: ...
    def transcribe(self, audio_path: str, language: str | None) -> TranscribeResponse: ...
```

Requirements:

- Instantiate `WhisperModel` **once** in `load()`, using `Settings`.
- `transcribe()`:
  - Normalize `language`: `None` means auto-detect.
  - Call `model.transcribe(path, beam_size=..., language=..., vad_filter=...)`.
  - Consume the segment generator into a list with sequential `id`.
  - Read language and probability from `info`.
  - Compute `duration_sec` from `info.duration`; fall back to the last segment `end`.
  - Build the Pydantic response.
- Keep the class free of FastAPI imports so it is unit-testable.
- No file writes, no printing; return data.

### 7.3 `main.py`

- `lifespan` async context manager:
  - Build `Settings`, call `transcriber.load()`, store on `app.state`.
  - On shutdown, drop the reference; no explicit unload required.
- `POST /transcribe`:
  - Accept `UploadFile` and optional `language` via `Form`.
  - Stream the upload to `tempfile.NamedTemporaryFile(delete=False, suffix=...)` in chunks (e.g., 1 MiB), enforcing the size cap.
  - Validate a content-type allowlist before inference:
    `audio/mpeg`, `audio/mp3`, `audio/wav`, `audio/x-wav`, `audio/webm`, `audio/ogg`, `audio/mp4`, `audio/x-m4a`, `video/webm`.
  - Acquire the semaphore with `WHISPER_QUEUE_TIMEOUT_SEC`; raise `503` on timeout.
  - Run `transcriber.transcribe` via `await asyncio.to_thread(...)`.
  - Delete the temp file in `finally`, including on cancellation.
  - Map exceptions:
    - `TranscriptionError` -> `400` for decode failures, `500` otherwise.
    - Semaphore timeout -> `503`.
- Log one structured line per request: request id, size, language, duration, inference ms, outcome. Never log audio content.

### 7.4 Concurrency and process model

- One model instance per process.
- `asyncio.Semaphore(WHISPER_MAX_CONCURRENCY)`.
- Run Uvicorn with **`--workers 1`**. Multiple workers would load multiple copies of the model and can exhaust memory.
- CPU thread count is left to `faster-whisper`/CTranslate2 defaults for now; revisit after benchmarking.
- Document that horizontal scaling means more containers, not more workers per container.

### 7.5 Error handling

- Define `TranscriptionError` for known failures.
- Treat `av` decode failures as `400` with a generic message (no stack traces to clients).
- Catch-all handler logs the traceback server-side and returns `500`.
- Ensure temp files are removed on every path, including client disconnect.

### 7.6 Readiness

- `model_loaded` is set only after a successful `load()`.
- Add `/health` readiness semantics; if the backend needs liveness separately, add `/health/live` in a later pass.

## 9. Tests

### Contract tests (`test_api.py`)

Use `httpx.AsyncClient(transport=ASGITransport(app=app))` and a fake transcriber injected into `app.state` to avoid model downloads.

Cases:

1. `GET /health` returns `model_loaded: true` with a fake loaded transcriber.
2. `POST /transcribe` success shape and field types.
3. Missing `file` -> `422`.
4. Empty file -> `400`.
5. Disallowed content type -> `400`.
6. Upload over the configured limit -> `413`.
7. `language` override is forwarded to the transcriber.
8. `language=auto` maps to `None`.
9. Transcriber raising `TranscriptionError` -> mapped error.
10. Semaphore timeout -> `503`.
11. Temp file is deleted after success and after failure.

### Integration test (`test_integration.py`)

- Marked `@pytest.mark.integration`, skipped unless `RUN_WHISPER_INTEGRATION=1`.
- Uses `tests/fixtures/sample_30s.mp3` and the real model.
- Asserts non-empty `segments`, `language == "es"`, and plausible `duration_sec`.
- Keeps runtime small; not part of the default fast test run.

### Acceptance criteria

- `pytest -m "not integration"` passes without network access or model download.
- Integration test passes locally with the model cache present.
- A 30 s fixture returns in a reasonable time and the response validates against the schema.

## 12. Security and limits

- No auth in Step 1: the service is intended for private network/local use only. Bind to `127.0.0.1` in development.
- Enforce upload size and content-type allowlist; treat content type as advisory and rely on decode failure as the real check.
- Never log audio bytes or transcripts.
- Keep the service free of third-party API keys.
- The leaked DeepSeek key in the legacy `main.py` must be rotated; do not copy it anywhere.

## 13. Risks and mitigations

| Risk | Mitigation |
|---|---|
| First startup downloads the model (slow, needs network). | Persistent `/models` volume; optional pre-baked image. |
| CPU inference is slow for long audio. | Async job model in the backend; service timeouts; document expected latency. |
| Multiple Uvicorn workers multiply memory usage. | Enforce `--workers 1`; scale with containers. |
| Large uploads fill disk or memory. | Stream to disk, enforce size cap, delete in `finally`. |
| Unsupported/corrupt audio. | Content-type allowlist plus decode-error mapping to `400`. |
| Client disconnects mid-inference. | Let `to_thread` finish or handle cancellation; always clean temp files. |
| Blocking the event loop. | Mandatory `asyncio.to_thread`; contract test that `/health` stays responsive during a fake slow transcription. |
| No diarization. | Explicitly out of scope; analysis fields depending on speakers stay `null`. |

## 14. Decisions to confirm before implementation

1. **Packaging:** `pyproject.toml` + `uv`/pip, or plain `requirements.txt`? (Recommend `pyproject.toml`.)
2. **Default language:** `es` (current behavior) or `auto`? (Recommend `es`, overridable per request.)
3. **VAD:** off by default (current behavior) or on? (Recommend off in Step 1 for parity; benchmark later.)
4. **Upload limit:** 100 MB enough? Any expected longer recordings?
5. **Legacy `main.py`:** keep untouched as reference, or replace it with a thin CLI calling the service? (Recommend keep untouched until Step 3.)
6. **API prefix:** expose routes at `/` or under `/v1`? (Recommend `/v1` if the service will be public; `/` is fine for internal.)
7. **`text` field:** include the concatenated transcript for caller convenience? (Recommend yes.)

Framework decision (FastAPI) is recorded in Section 2 and is not open for this step.

## 17. Implementation notes (as built)

- The service lives in `app/` at the repository root; the `services/whisper/` split was deferred to avoid restructuring the repo.
- Docker was deferred; the service runs locally with `uv`.
- `av<19` is pinned because `faster-whisper 1.2.1` calls `av.open(..., metadata_errors=...)`, which PyAV 19 removed.
- The legacy batch script was moved to `legacy/main_batch.py`; its hardcoded API key was removed and its LLM block is disabled.
- `openai` was removed from the Python dependencies; the LLM call belongs to the Bun/Fastify backend.
- Verified locally: 12 contract tests pass offline, the real-model integration test passes on a 20-second fixture, and an end-to-end HTTP request returns a valid transcript.
- The existing `20261019_fastapi_1.mp3` file is silent (`mean_volume: -91 dB`), so it produces an empty transcript; use `tests/fixtures/sample_20s.mp3` for verification.
